# G-003 M2 — the app on Linux (2026-10-12)

What was run to show the app works on Linux, on WSL Ubuntu 24.04 under WSLg (4.8 GB given to WSL), and
that Windows is unchanged.

## Gates
Final run, after the /code-review fixes:
- Windows `scripts/check.ps1` on `MemoryMap.slnx`: format clean, build 0 warnings, 285 tests, 277 passed,
  8 skipped (the Linux-only tests: seven process-action tests and the live /proc test).
- WSL, the same steps on `MemoryMap.slnx` (WSL has no pwsh, so they were run by hand), twice: format
  clean, build clean, 202/202 (the Windows tests are not a test project there, D030);
  `scripts/crosscheck-linux.py` PASS, worst difference 0.17% of RAM.

## The window under WSLg
Run from a Release build, with libICE and libSM unpacked from their .debs into the user's home. The
package will depend on them; WSL's image lacks them.
- Map: Linux groups drawn; "Programs not visible here" about 1.1 GB (Docker Desktop's distribution in
  another PID namespace, D026); 44 processes. Private memory (RssAnon) of the app itself 43 MB.
- Table: every group and figure listed. The first run showed the "RAM" and "Processes" headers touching
  (the Linux font is wider than Segoe UI); the table and Startup grids now space their columns, checked
  again on WSLg.
- History: lines and legend drawn, "Kernel allocations" named as on Windows.
- Settings: the tray checkbox is greyed with the no-tray note (WSLg shows no tray icons), and the footer
  names `/home/<user>/.config/MemoryMap/settings.json`. Raising "Warn below" from 10 to 11 wrote
  `AlertBelowPercent: 11` to that file at once.
- Closing: one click on the window's close button ended the process (no tray host, so closing quits);
  the log was empty. A WM_CLOSE posted to WSLg's host window was not passed on to the X11 window, so the
  click is the test.
- Startup tab: says there is no startup list on this system (M3 adds it).

## After /simplify
- Fixed: tray availability had three owners (a settings property, a window delegate, a startup probe)
  and was asked on the UI thread at each close; `TrayHost` now owns it and asks off the UI thread (D031).
  Boot time and the app's own uid are read once per actions object; `ProcText.Uid`, `ExePath` and
  `ReadRequired` are shared by the sampler and the actions; `PidFd` signals itself.
- Kept, with reason: the History pixel test reads a 3-row column (anti-aliasing puts the line on a
  different row on Linux; the colour at that x is still asserted); the start-time check stays after the
  pidfd is opened (so it checks the pinned process); Core's per-OS denial sentences stay (only Windows
  reaches `Critical`).

## After /code-review
- Fixed: boot time is read once per `/proc` and shared, so sampler and actions cannot disagree by the
  second `btime` can jitter; the init test no longer depends on the user name (End refuses PID 1 as
  critical before any signal, and the other-user test only locates, skipped when init is ours); our uid
  comes from `getuid()`, and an unreadable uid is another user's; a pidfd refused with EPERM (seccomp)
  falls back to `kill` as ENOSYS does; a close whose tray probe fails quits, a second close waits for
  the first answer, and a desktop known to have no tray closes at once; a `dbus-send` that exits between
  the timeout and the kill no longer throws. The Critical message no longer names Windows.
- Found while rerunning: the "lost its tray" test raced the thread pool on Linux (the answer came before
  the check); the probe now waits on a gate.
- Kept, with reason: `xdg-open` still running after 5 s counts as shown (it stays with the file manager);
  the 3-row pixel column (above).

## Not checked

- A desktop with a tray host: WSLg has none. Hiding to a real tray is on the Owner's checklist (M4).
