# Decisions — memory-map

- D001 — Avalonia for the desktop UI — active
- D002 — Native APIs, not WMI, for the 1 s sampler — active
- D003 — A process tile's size is its private working set — active
- D004 — dotnet format, xUnit v3 on Microsoft Testing Platform, local check script — active
- D005 — One node tree for the breakdown; the sampler tags each process's kind — active
- D006 — xUnit v3 pinned to 3.2.2 for Avalonia's headless test runner — active
- D007 — Scene arrangement, hit-testing and tooltip text live in Core, not the UI — active
- D008 — Process actions re-check the start time and never end several processes at once — active
- D009 — Drill-down keeps a chain of node keys and falls back to the nearest ancestor — active
- D010 — History keeps one point a second for an hour, with every app's size — active
- D011 — The low-memory alert warns once, re-arms 2 points higher, and shows its own window — active
- D012 — Chart lines use the validated categorical palette, and an app keeps its slot — active
- D013 — Settings live in %APPDATA%\MemoryMap\settings.json and save on every change — active
- D014 — The installed app is one self-contained, uncompressed, untrimmed exe — superseded by D043
- D015 — The app renders in software, not on the GPU — active
- D016 — A Settings option slows sampling while the window is hidden; off by default — active
- D017 — The map redraws on every refresh; skipping unchanged frames was measured and dropped — active
- D018 — Startup entries come from the Run keys, Startup folders and Store tasks, with Explorer's StartupApproved flags — active
- D019 — Store apps' startup tasks are read from the AppModel registry and package manifests — active
- D020 — An entry that starts a host program (cmd, rundll32, a script host) is credited with no processes — active
- D021 — A startup switch writes the same StartupApproved bytes Windows Settings writes — active
- D022 — The startup list is read when the tab opens; samples are matched only while it is shown — active
- D023 — The code lives in a private GitHub repo; CI runs the local gate on a Windows runner — private repo superseded by D039
- D024 — Machine-wide startup changes run this exe elevated in a one-shot helper mode — active
- D025 — System memory is OS-neutral: totals, named figures and names, all supplied by the sampler — active
- D026 — A Linux process is sized by RssAnon; memory of processes not visible is its own figure — active
- D027 — A Linux process's kind comes from its name, cgroup and account — active
- D028 — CI runs the gate on Windows and Ubuntu; Linux covers a solution filter until M2 — filter superseded by D030
- D029 — Linux process actions act on the user's own processes, through a pidfd — active
- D030 — The gate builds the whole solution on both OSes; Windows tests run only on Windows — active
- D031 — Close-to-tray asks the desktop for a tray host at each close — active
- D032 — An XDG autostart entry is switched through a marked per-user copy — active
- D033 — systemd user services are listed read-only — active
- D034 — A Linux startup program is matched by its resolved file; hosts and bare scripts are not counted — active
- D035 — Linux ships as a self-extracting single file and a .deb with its libraries beside the program — active
- D036 — The .deb declares measured dependencies and keeps Skia's embedded libraries — active
- D037 — Without titles a group is an outline, and the whole frame answers the pointer — active
- D038 — The app's own code is MIT-licensed, credited to yunniko and Claude — active
- D039 — The repo and its releases are public — active
- D040 — Releases are built by a tag-triggered workflow; SignPath signs the Windows exe — active
- D041 — Linux packages are built for amd64 and arm64, each on its own architecture's runner — active
- D042 — Windows shell COM calls use generated interop, and settings JSON a generated context — active
- D043 — The published app is a Native AOT build, with its two native libraries beside it — active
- D044 — AOT releases: a flat Windows zip, Linux tarballs with a folder, the published app run in CI — active
